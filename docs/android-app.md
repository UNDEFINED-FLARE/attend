# UniAttend Android app

The Android app is a native shell (Capacitor 8) around the deployed UniAttend web app. Every screen, check-in rule
and permission check still runs on the server, so:

- web changes reach phones immediately, with no Play Store update;
- the app needs a connection (check-in uses the live QR code anyway). Without one it shows an offline screen with
  *Try again*;
- QR scanning uses the phone camera and check-in uses the phone GPS. Android asks for each permission the first time.

| Item | Where |
|---|---|
| Web address the app opens | `mobile/app.json` → `url` |
| App id (permanent once on Google Play) | `mobile/app.json` → `appId` (`za.uniattend.app`) |
| Native project | `android/` (generated by Capacitor, then customised: permissions, icons, no cloud backup) |
| Offline / start screens | `mobile/www/` |
| Icons and splash | `node scripts/mobile-assets.mjs` draws them from the UniAttend mark |

## 1. Set the web address

Edit `mobile/app.json` and put your deployed address in `url`, e.g. `https://uniattend-xyz.vercel.app`.
Also add that address to Supabase → Auth → URL configuration if it isn't there yet.

## 2. Build a test APK

**On GitHub (no Android Studio needed):** Actions → *Android app* → *Run workflow* (optionally type the web address).
When it finishes, download **uniattend-debug-apk** from the run's *Artifacts*, unzip it, copy `app-debug.apk` to the phone
and open it (allow "install unknown apps" once).

**On this PC** (needs JDK 21 and the Android SDK, both installed here):

```bash
npm run android:build
```

The APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`. To try the app against a local dev server in the
emulator, use `node scripts/mobile.mjs build --url http://10.0.2.2:3001` (10.0.2.2 is this PC as seen from the emulator).

## 3. Publish on Google Play

1. Create an upload key once and keep it safe (losing it means you can't update the app):
   ```bash
   keytool -genkeypair -v -keystore uniattend-release.jks -alias uniattend -keyalg RSA -keysize 2048 -validity 10000
   ```
2. Create `android/keystore.properties` (never committed; `.gitignore` covers it):
   ```
   storeFile=../../uniattend-release.jks
   storePassword=…
   keyAlias=uniattend
   keyPassword=…
   ```
3. Raise `versionCode` (and `versionName`) in `android/app/build.gradle` for every upload.
4. Build the bundle and upload `android/app/build/outputs/bundle/release/app-release.aab` in the Play Console:
   ```bash
   npm run android:release
   ```

Play Console needs a privacy policy URL (`/privacy` on your site) and the data-safety form. The app collects
location at check-in (used once, only the distance is stored), the camera for QR scanning (not stored), and a device hash.

## Notes

- **Bluetooth presence** isn't possible from the web app. In this native shell it can be added later with a BLE plugin,
  for example lecturer phone as beacon and student phone scanning for it. That would need new evidence in `check_in()`.
- **Email confirmation links** open in the phone's browser. After confirming, sign in in the app.
- The app keeps sign-in and the device id on the phone only: Android backup and device transfer are switched off.
